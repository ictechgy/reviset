These are native UI recovery actions, not changes to stateless MCP API request semantics.

Only initial report loading or an explicit new workbook version pair can select the first eligible linked cell change after a successful query. Method changes, fallback, retry, paging, locale/layout changes and passive refresh retain independently valid physical readers. Missing, null, empty, materialized blank, partial, exhausted and unavailable fields remain distinct. A value field can be exhausted while a formula still has Next. Formulas are not recalculated. New comparison requires two version entries; a supplied PPTX/PDF pair counts as one. Ordinary one-version reading remains available.
