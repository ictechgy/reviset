## Repairs

| Area | Problem and resulting behavior |
| --- | --- |
| PPTX archive admission | Forged ZIP sizes could bypass resource checks. Extraction and rendering now share strict header, path, member-type, size, descriptor, overlap and CRC validation. Deflate output is bounded before acceptance; unsupported or contradictory archives fail explicitly. |
| Original identity | A changed private import could be treated as a fresh original during reanalysis. Persisted expected hashes now reach parsing, and every cached occurrence is rechecked. A mismatch aborts with `SOURCE_CHANGED` and preserves prior fixed reports. |
| Filesystem input | A replaced input could become a FIFO, symlink or oversized file. Import, analysis, hashing, CLI preview and standalone PPTX conversion now use a bounded regular-file descriptor. The CLI preview reads once and passes those exact bytes onward. |
| Durable saves | Cleanup failure or a lost bridge reply could make a saved report appear unsuccessful. Cleanup is separate from the durable commit; exact project/run reconciliation retrieves the saved report or retains explicit uncertainty. Warnings survive a newer selection. |
| Native reliability | A dead helper pipe no longer terminates the app through SIGPIPE. Numeric decoding avoids trapping conversions. Failed workbook import restores interrupted reads only while their owning view remains current. |
| Evidence navigation | Page selections remain tied to the selected occurrence. PDFKit internal navigation cannot silently change the model-owned page, and rejected navigation preserves the zoomed viewport. Explicit page/zoom changes supersede queued restoration. |
| Workbook selection | Row-header clicks select the actual physical row with the current valid column. Header reuse clears stale accessibility labels; bounds and duplicate-selection guards remain shared with ordinary cell selection. |
| History rendering | The history view indexes primary pages once per projection instead of repeatedly scanning all pages for each lineage. Regression checks preserve ordering and duplicate-occurrence behavior; this is not a new throughput benchmark. |
| Contracts and diagnostics | Native document input errors are translated while retaining their original codes. Spreadsheet/MCP documentation distinguishes explicit covered-cell observations from absent cells, explains format budgets, and states that cell history stops conservatively at a sheet rename. |

The stricter PPTX parser deliberately rejects ZIP64, noncanonical paths, unsupported compression and inconsistent archives. Supported regular files are covered by normal conversion controls and five pinned public PPTX extraction/admission controls. These checks do not establish PowerPoint rendering fidelity. See [support limits](../README.md#support-and-limits) and the [spreadsheet contract](SPREADSHEETS.md).

No engine/report schema version or archived comparison kernel was changed. Existing report identities, storage paths and `docver://` resource compatibility remain intact; see [rename compatibility](RENAMING.md).
