# Workspace customization

Use **Layout / 화면 배치** in either native workspace to arrange its source comparison and supporting panels. Document and spreadsheet layouts are saved separately.

- Start with **Source first**: Changes on the left, large source comparison, projects and evidence closed. This is the new default and reset target. Balanced, Document Focus, Review and saved layouts remain available. Existing saved preferences are retained; apply Source first explicitly to try the new arrangement. Reset never deletes a project or report.
- Drag the native splitters to change panel sizes and the before/after ratio.
- Place Changes below, left, or right of the comparison. Hide supporting panels when you need more document space; place the evidence inspector on either side.
- Switch between horizontal and vertical source comparison.
- On both platforms, toggle Document Focus to temporarily enlarge the source. Toggling Focus off restores the preceding panels with geometry edits made while focused. Opening a panel during Focus restores the retained arrangement and merges only the changed visibility flags. Saving during Focus records that retained arrangement with edited geometry and keeps Focus active. Applying a preset, saved layout or reset starts a new baseline. Independently hiding panels, even all of them, keeps report and history-range controls available.
- Save a named layout, apply it later, or delete the saved layout. Up to twelve names are stored per workspace. Cancelling the save dialog writes nothing.

Layout changes retain the existing report, source hosts, selected pages/cells and viewing state. Display preferences never enter canonical reports, exported machine data or MCP responses. Source text and user-authored names are not interpreted as format strings or instructions.

On macOS, the View menu shortcuts act on the active document or spreadsheet window: `⌘⌥F` for focus, `⌘⌥I` for evidence, `⌘⌥S` for projects, `⌘⌥C` for changes, and `⌘⌥0` for reset. The toolbar layout menu exposes docking, presets and named layouts. Windows provides native menus and keyboard-focusable splitters.

The workspace title shows the literal project name. Settings are versioned and size-limited. Unsupported positions and invalid dimensions recover to safe defaults. Future-schema settings are preserved without overwrite. Window size constraints can temporarily limit visible space without replacing the user's preferred panel dimensions.

The fixed report and query controls stay available in Focus. The comparison interval belongs to the change list; source headers identify the selected event's actual versions/pages/cells. Selecting an intermediate event keeps the wider query interval. Previous/next change actions stay in the same list. A text-diff view provides bounded before/after snippets with `−/+` markers while retaining the native source hosts; appearance observations and unavailable content use neutral labels rather than semantic deletion markers. Detailed source evidence remains available separately. Missing, empty, materialized blank, partial, invalid and already-read observations are distinct. A materialized blank, absent formula and missing saved result have distinct captions. A cell event without one side's observation denotes an unmaterialized cell even if its sheet exists; sheet-metadata captions are reserved for sheet-scoped events. An absent sheet stays neutral without failing the opposite grid. Long or transport-shortened text is bounded neutral evidence; independently clipped prefixes are not coloured as complete semantic edits. Formula-source and saved-result eligibility is assessed separately. Association and event-kind authorization are assessed before field-specific cache, interpretation, type or dialect reasons; number-format observations stay neutral. Raw source text, user-authored reasons and UTF-16 continuation ranges remain literal in either interface language.

The version-history menu opens a version against its predecessor. Selecting the first version or equal query endpoints opens a single source. When several versions are imported, choose different endpoints to compare. With only one imported version, the visible **New comparison / Import versions** action creates a new timeline with at least two version entries, rather than appending to the current immutable report; the reading screen does not claim that a comparison found no changes. The document list visibly identifies **stored adjacent events**, **computed endpoint changes** or **stored interval history**. Neighboring two-version choices use canonical stored events; wider Net choices compute endpoints. History uses stored events. A fresh document API `range_net` always recomputes and can differ from stored adjacent events in structural kinds and manually reserved/unlinked correspondence. Workbook `range_net` follows its own contract and uses stored events for adjacent versions. Content that changed and later reverted can therefore have no endpoint difference and still have an intermediate history. Manual page, sheet or cell browsing retains the current paged list and its query interval. It does not turn an unrelated source pair into the selected event's text edit; use **Return to selected change** to restore its source pair and scoped navigation anchor. Document manual-page anchors expire when their report or source pair changes. On Windows, use query endpoints and the version log to choose versions; source headers show the displayed version and sheet. These choices start with valid sheets.

In narrow Windows windows, Changes and Evidence can adapt to the bottom without replacing saved panel preferences. Native splitter grips remain available; the source header identifies the focused pane. A visible project panel remains accessible. Hide it explicitly from Layout or choose Document Focus to give the source more room. The Net/History selector retains the selected version interval.

For document UI stored IDs, use the same fixed report and a containing occurrence interval with `list_changes(mode:history)`, then `get_change(change_id, component, from, to)` **without mode**. Follow component row/text continuations; a newly computed `range_net` is a separate result. See the [exact MCP recipe](MCP.md#recovering-the-document-uis-stored-change-ids).

Diff comparison budgets intentionally differ: macOS allows 4,096 UTF-16 units and 128 lines per side; Windows allows 16,384 units and 300 lines per side. Complete workbook cell fields beyond a diff budget remain readable neutrally; document text overlays disclose their bounded selected-event excerpt scope and keep the original-source/evidence route available. CR, LF, CRLF and EOF remain exact in stored data. macOS visible markers identify each line's terminator boundary separately; current Windows captures do not establish marker parity. Combining all terminators into one string does not establish equal per-line boundaries. A trailing CR, LF or CRLF belongs to its existing line; it does not create a phantom empty EOF row. Exactly 128 newline-terminated lines fit the Mac line budget, subject to its character budget. The markers never rewrite source. Bounded previews and continuation/full-reader limits remain explicit. Grid tooltips identify bounded previews and direct readers to selected-cell/source continuations for the full field. Generated change summaries are localized; source values, names, formulas, human reasons and raw report descriptions remain verbatim.

Changing locale, busy/diagnostic state or opening report/AI detail preserves the manually scrolled text viewport and surrounding arrangement when source identity is unchanged. Native accessibility labels follow the selected language.

## Source reading and recovery

Query, selected-event and physical-source failures have separate recovery routes. A failed Windows query retains independently verified sources and raw readers; its Retry repeats the failed reset or append query. Raw-reader Retry repeats its captured physical source, side, component, UTF-16 offset, cursor and limit. Successful query recovery does not automatically select another event. The [qualification record](NATIVE-GIT-DIFF-2026-10-24.md#reading-and-recovery-contract) records the exact ownership contract.

Each workbook text heading names its actual occurrence, sheet or explicitly absent sheet, and physical cell address. Sheet-scoped metadata uses metadata captions without unmaterialized-cell warnings or cell-field rows. A selected event side with no cell does not inherit an old address. Unknown value types remain neutral observations.

A visible localized **Cell details** action opens the focused physical cell's existing bounded reader and continuation route while retaining the query/list and native hosts. One-version warnings, navigation and reader footer describe the single source. Text-mode navigation explicitly returns to original-source browsing.

An event source-read failure preserves a still-valid paged query. Retry belongs to the intended event, fixed report, interval, mode and current membership; a previous event's anchors cannot describe the failed target. Superseded failures cannot install retry authority. Query failure requires query recovery rather than reusing unverified rows.

Windows reference-PDF previews use that PDF's own physical dimensions; primary PPTX dimensions retain OOXML EMU authority and normal conversion to points. Headers refresh as displayed occurrences change through event selection, restoration or clearing. Legitimately absent sources are neutral terminal states. Startup recovery failure keeps writer actions disabled until explicit recovery succeeds, with the exclusive library lock enforced before opening the window. Range metadata, omitted page lists, diagnostics and preview status must not imply complete verified observations.

## Reading wide or long sources

Initial grid columns stay compact and stable while observations load or a result is empty. Explicit resizing retains the chosen width for that source. Windows rows follow physical coordinates rather than header sorting. Each source pane has its own zoom and **Fit** action: PDF Fit uses page width and structural views use their fitted layout.

Resize or hide supporting panels when the source needs more room. A layout change preserves the current zoom and manual viewport where feasible; a narrow pane at a chosen manual zoom can show only part of a PDF page. Use the pane's zoom or Fit controls and native scrollbars to inspect the remaining source. Workbook grids also scroll horizontally; selecting a cell change reveals that selected cell rather than unrelated off-screen changes.

Large projects still need memory for analysis and fixed reports. Paged lists, sparse grids and bounded previews control view payloads, not the entire process footprint. See the [Windows scaling limits](WINDOWS.md#large-documents-and-workbooks) and source-bound [public-corpus measurements](PUBLIC-CORPUS-FIXES-2026-10-23.md).

The Mac physical row-address gutter stays visible during horizontal grid scrolling. Opening Cell Details explicitly reveals the inspected cell horizontally. Windows bounds and scrolls inline details while retaining a useful grid area. Reading an oversized field may expose only a leading fragment; use the bounded reader and continuations for the stored field.
