# ADR-004: native raster evidence, local OCR and actual PPTX rendering

2026-10-19. The user requires continued improvements to PDF interpretation, OCR and PPTX rendering fidelity. This supersedes ADR-003's initial no-OCR / PPTX-structure-only checkpoint.

The app bundles a Swift Vision/PDFKit helper and an unmodified signed LibreOffice app. These are local subprocesses behind the existing SwiftUI/AppKit UI and staged Node compute/atomic commit boundary. The renderer receives a validated copy of the exact imported bytes, never a mutable path re-read. Macro/OLE and external-resource relationships are rejected before rendering; ordinary web/mail hyperlinks remain links. XML relationships are parsed and entity-decoded, including nested XLSX chart packages. LibreOffice has its own profile, HOME, temp/font caches, no IP network access, and writes restricted to temporary paths/devices. Local Unix IPC remains available for its bootstrap. A timeout or cancellation kills the owned process group and cleans the job. Vendor signatures and the pinned official DMG digest are checked; the outer app preserves the TDF signature. Python bytecode writes into the vendor bundle are disabled.

Headless LibreOffice uses explicit system/user/bundled fontconfig directories. Without this, an empirical test lost Korean text even though AppleGothic was installed. System fonts are read, not redistributed. The font inventory, OS/build, renderer version/binary/config and output hash are observation provenance. Hidden slides are exported; page count and aspect ratio must agree before source-to-render mapping is used. Missing fonts, omitted extracted text and unsupported object semantics remain explicit warnings. The converted PDF is a derived asset. When an imported same-version PDF has a content-consistent mapping, the native viewer uses that exact PDF first.

PDFKit's cropped/rotated native appearance is captured in bounded batches of at most sixteen pages. OCR uses Vision revision3, accurate Korean/English, correction off, 300-DPI target / 4096-pixel dimension cap. Overlapping tiles and focused numeric crops cross-check values. macOS26+ RecognizeDocumentsRequest revision1 supplies inferred table cells; earlier supported OS versions preserve the unavailable structure status. Confidence is an uncalibrated model score, not probability. The 0.5 threshold plus numeric consensus is exercised on synthetic cases; this is not a broad-corpus accuracy claim.

Raw PDF text, original visible/suppressed/unresolved layers and the OCR annex remain separate. The selected comparison basis is explicit. An unresolved raw layer can use separately labeled raster OCR for an inferred comparison, without changing the original visibility assessment. OCR never proves absence. Unpaired/missing OCR regions, ambiguity or uncertain values withhold precise text change; source-review gaps remain. Unique readable numeric regions may be compared independently with text_scope=region while other regions stay unresolved. Pixel strike heuristics produce inferred candidates, never author intent.

Identical native raster hashes suppress text-only differences, including nondeterministic OCR or hidden source changes. Different native pixels can produce visual_region_changed, with no semantic deletion claim; cross-format renderer contributions remain inferred. Source annotation state changes without native pixel change remain marked. The same raster hash and environment can reuse OCR across versions, while raw extraction stays source-specific. Source, pixel and environment cache identities are validated independently.

Reports retain the canonical complete snapshot. Native page projections are additionally stored in SQLite within the same report/run/latest transaction; source hash checks stream bytes without allocating the entire source on every page navigation. Old reports can fall back to canonical loading without rewriting them. MCP remains read-only and uses the canonical snapshot/query contract. Page indexing reduces navigation memory; it does not remove full-snapshot parsing from all query/view/commit paths.

Range-net queries bind to the snapshot's engine version. The released 0.1.0-native.1 diff kernel is archived from commit6a736379; current snapshots use the new kernel. Unknown historical engines fail explicitly for recomputed ranges while stored history/export remain readable. New fixes never silently reinterpret an old snapshot's range under the current kernel.

The broader quality gate is empirical: real OCR, rotated/cropped geometry, raster strike/underline controls, missing-region guards, font-aware conversion, hidden-page mapping, fixed derived bytes, immutable report/page indexes, cancellation and actual packaged app execution. Office reference exports are independent upstream-declared PowerPoint outputs with pinned hashes. Nonzero pixel differences are recorded as failures of strict pixel equivalence, never rebranded as an accuracy percentage. The user-selected reference environment, licensed source fonts, broad real-document corpus and any remaining discrepancies must be resolved before claiming universal fidelity.
