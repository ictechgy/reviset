# Spreadsheet version history · implementation contract

Status: workbook engine 1.1 implementation, 2026-10-23. This is an additive workbook feature. Existing document schema/engine identities, archived kernels, original HANDOFF.md/PLAN.md, and qualified apps/ZIPs remain unchanged.

The feature reads XLSX, ODS and UTF-8 CSV as sparse workbook/sheet/cell observations, preserving typed lexical values, formulas, saved formula results, basic number format/style, merged ranges, hidden sheets/rows/columns and explicit coverage gaps. It never executes macros, external links, formulas or embedded objects. Unsupported binary/encrypted formats fail explicitly. Stored formula results may be missing/stale and are never certified recalculations. PDF rendering cannot establish cell or formula identity.

Workbook reports use the separate `workbook.1` schema and SQLite tables on the existing Store connection. New analyses use engine `workbook.1.1`. Readers retain immutable `workbook.1.0` report identities and the historical diff path for their original cell observations; a 1.0 report is rejected if it contains 1.1-only blank-formatting fields or events. Project/report/occurrence/sheet IDs bind every read. Original assets use the existing verified content-addressed store. Source observations are immutable; row/sheet associations are inferred and labelled, ambiguous correspondence is not semantic deletion. Formula-source differences and cached-value changes are separate. Formatting IDs and ZIP/XML order are not semantic identities. Cross-format comparisons retain capability gaps. Empty ODS covered cells remain materialized observations, so merged-cell representations can differ from XLSX sparse absence without asserting a deletion. Cell history currently follows a unique key within the same sheet name; a rename stops it with `correspondence_unresolved`, even when a diff separately inferred a unique content-based sheet match. Use the fixed-version cell reads and explicit change evidence to inspect that boundary.

Native UI is an additional workbook workspace/window in the same SwiftUI/AppKit app, using its existing Bridge and exclusive library lock. A large, virtualized AppKit grid supports sheet/version selection, physical cell addresses, previous/next changes, explicit alignment method, raw formula/value details, hidden-content labels and available/unsupported states. Existing document workspace remains unchanged. A superseded query cannot publish into another project/report/selection. Analysis uses existing owned cancellation and analyze→commit semantics, with no commit on cancelled/stale runs.

Bridge action contract (outer document bridge protocol remains unchanged):

- workbookProjects → project summaries; workbookCreate({title,revisions:[{label,path,expected_sha256?}]}) → {project_id,...}.
- workbookAnalyze({project_id}) → staged result; workbookCommit({project_id,result}) → {report_id,...}; workbookReports({project_id}) → fixed report summaries.
- workbookView({project_id,report_id}) → metadata, revisions with occurrence IDs and sheet summaries, coverage, change counts. No full cell matrices.
- workbookQuery({name,args}) invokes the same read-only query contract as MCP. The 13 tools are: list_workbook_projects, list_workbook_reports, get_workbook_report, list_workbook_revisions, list_workbook_sheets, list_workbook_formatting_ranges, get_workbook_range, get_workbook_cell, list_workbook_changes, get_workbook_change, search_workbook_cells, get_workbook_cell_history, list_workbook_coverage_gaps. All scoped reads require project_id/report_id, version reads revision_occurrence_id, cell reads sheet_id and physical row/column. get_workbook_range uses row_start/row_limit/column_start/column_limit. list_workbook_formatting_ranges pages stored compressed blank-style rectangles within one occurrence/sheet, including ranges outside the visible viewport; materialized style-only cells remain available through ordinary cell/range reads. list_workbook_changes uses from/to occurrence IDs and mode=history|range_net. Output items and next_cursor are bounded; text continuation distinguishes truncated/missing/empty data. No paths or arbitrary reads through MCP.
- workbookExport({project_id,report_id,folder}) exports quoted Markdown and JSON/JSONL with fixed IDs. workbookPublish({project_id,report_id,label,reason}) creates an immutable, local release record; it does not send anything, authenticate an editor, or establish a server permission boundary. workbookReleases({project_id}) lists records; exports include their provenance.

Initial limits must be enforced before expansion: input 64MiB, expanded archive128MiB, part32MiB, 100 sheets, 500,000 materialized cells, 1,048,576 rows/16,384 columns, finite parser/XML/cell-string budgets. ODS repeated blanks must not allocate a dense workbook. CSV is UTF-8, RFC-style quoted fields with comma delimiter; other encodings/dialects are explicit limits. These bounds are not measured throughput guarantees.

Required validation: independent synthetic source truth; XLSX/ODS/CSV import; formula→constant with equal saved result; missing/stale formula cache; zero/blank/text/number/date; Unicode/quotes; styles and hidden content; row insertion/reorder and duplicate/ambiguous keys; cross-format coverage; historical net vs intermediate events; A→B→A recurrence; project scope/cursor tampering/text paging; cancelled/stale analysis; corrupt asset/draft; hostile ZIP/XML/repetition/external links; actual native app and packaged MCP; relocated app/ZIP. Heavy compile/OCR/Office/full-suite/package jobs run serially. Real Excel/Calc originals must remain byte-identical. No claim of full Excel/Calc rendering or calculation compatibility.

## Design consultation closure requirements

The first Claude proposal review identified gaps in the initial prose, not established runtime defects. Implementation must enforce these invariants: staged descriptors reference server-owned bytes/run records and are checked against active run status, project, draft hash, ordered source identities and engine/schema on commit. They never carry a caller-supplied full report. A cancelled/stale run cannot commit. Single Bridge analysis admission spans document/workbook windows; owner UUID gates cancellation. Parser limits, malformed repeat spans, excessive XML/shared strings and unsupported encryption fail the input before a partial observation can reach diff. Small explicitly cell-styled empty observations count against the materialization budget. Contentless, explicit nondefault style repetitions whose row-by-column area exceeds 64 are retained as bounded `blank_style_ranges`, with an independent rectangle budget; their cell area is not expanded during ingestion. Contentless blank tails whose only formatting comes from row/column defaults stay sparse with a `row_column_default_styles` gap; formatting equality is not claimed for those unmaterialized rectangles. Only a complete covered cell extraction may emit literaltrue cell_extraction_complete; unavailable advanced features remain explicit gaps.

Every formula has cached_result=present|missing, unknown freshness and an explicit dialect. Non-formula cells use not_applicable. Empty saved strings differ from missing caches; missing results are coverage, never blank-value deletion. CSV remains untyped strings and lacks formula/style/visibility authority. Cross-dialect formulas are not semantically equated or marked as formula edits. Exact decimal comparison may normalize lexical forms while retaining source text; date systems remain separate and serials remain raw. Source refs are in-package locators, not host paths. Unsupported defined names, validation, conditional formatting, comments, pivots/charts and external links are named gaps when encountered.

Native workbookGrid is a separate read API backed by sparse indexes, bounded to100rows×12columns/1200cells and1MiB, with value/formula previews at64UTF16 units and explicit truncated flags/source lengths. Preview snippets are not raw evidence. Selected cell and MCP reads retain full paged original text. Published records are local, explicitly user-labelled and bound to fixed report/schema/engine; they do not prove the true editor of imported files. Public deployment/sending remains separate from this local feature.

## Formula interpretation and resource limits

Shared/array/spill/matrix formulas can store results in cells without an ordinary formula source. Such observed cells carry `formula_interpretation=unresolved`, retain raw saved values/formula fragments, and have unknown cached-result freshness. Formula/input conversion and value-type changes are not asserted from this incomplete interpretation; changed raw observations require review. Unsafe/missing affected ranges conservatively mark the sheet rather than allocating a rectangle or certifying direct inputs.

The aggregate report limit is 500,000 materialized cells across all revisions, 100,000 stored blank-style rectangles, 100,000 changes and 256 MiB canonical serialized JSON; originals remain at most 64 MiB. These limits apply jointly. Sparse grids do not deserialize the full report. Analysis, full lineage and endpoint diff can require substantial memory; a limit is not a throughput guarantee. The native helper uses a 2 GiB V8 heap bound. Actual measured size, peak RSS and elapsed times are recorded separately from limits.

## Explicit blank formatting in engine 1.1

ODS repetitions preserve explicit nondefault style observations as either materialized cells marked `blank_style_only` or compressed `blank_style_ranges`. A compressed range retains inclusive row/column bounds, style/number-format evidence, hidden-axis state and its in-package `source_ref`. Known validation/protection attributes (`table:content-validation-name`, `table:protect`, `table:protected`) alone do not materialize empty repetitions; `data_validation` and `cell_protection` sheet gaps expose their unsupported semantics, while original attributes remain in the retained file. Explicit cell styles, including inherited properties, remain observable independently. Values, formulas, covered/merged/matrix cells, child content such as comments, and all other attributes (including `calcext:value-type` and unknown attributes) remain subject to the materialized-cell limit. Unknown attributes are intentionally fail-closed for sparse classification: compared with the earlier permissive blank-tail behavior, a repeated cell with an unrecognized attribute can now reach the materialized-cell rejection limit. This avoids silently discarding a future value-bearing extension. Attribute classification resolves namespace URIs before canonicalizing recognized prefixes, so equivalent XML prefix aliases have the same behavior; a familiar local name in an unknown namespace does not inherit the exception. Row/column defaults on absent cells remain a separate coverage gap. A rectangle intersecting unresolved matrix/formula-dependent regions carries conservative unresolved provenance; it is not certified as an ordinary blank input.

Both representations use physical `formatting_range` change observations when the source formats match. The compression threshold does not select a different change kind or imply inferred row lineage. Cross-format style equivalence remains unsupported. Pre-1.1 reports have no `blank_style_only` markers and retain their original cell-diff semantics.

When a one-sided material cell has an explicit blank observation at the same physical coordinate in the other version, the diff retains both endpoints in a `cell_observation` marked `needs_review` with `physical_blank_content_coordinate` alignment. A compressed blank keeps its original `source_range` and a one-coordinate `difference_range`. Same-format style, number-format and visibility differences are separately observable. Occupied coordinates are excluded from blank-formatting bands, so retained content formatting is not reported as a missing blank observation. Explicit blank markers are excluded from content-row matching across formats, so compression does not change the confidence of a blank/content observation. Existing inferred content-to-content row moves still use their ordinary comparison; supported formatting differences at their masked physical blank/content coordinates remain separate `needs_review` observations. Unchanged physical formatting does not add a content-transition event for a matched move. Physical blank pairing does not establish row lineage or assert the cause of a change.

Equivalent blank-style encodings compare equal. When styles differ, event segmentation, counts and IDs can follow the original rectangle/cell boundaries; adjacent bands are not coalesced across different source locators. Different writer encodings can therefore reach the declared change/work limits at different sizes. This preserves exact source provenance rather than promising encoding-independent change IDs.

Mixed-format reports include one `cross_format_blank_formatting` coverage gap per source occurrence/sheet with explicit blank styles, including materialized style-only cells and sources used only in nonadjacent endpoint comparisons. `list_workbook_coverage_gaps` exposes it with occurrence and sheet filters. Cross-format `list_workbook_changes` responses for affected comparisons also return `blank_formatting_comparison=unsupported_across_formats`, a gap count and the coverage query, even when no formatting events are returned. `blank_formatting_coverage_scope=comparison_interval` means this warning and count survive sheet/kind filters; history considers adjacent comparisons and range_net considers its endpoints. An empty change list does not certify unchanged blank formatting across formats. Same-format comparisons and historical engine 1.0 query responses retain their prior semantics.

Renaming a sheet while changing its blank-style encoding between compressed rectangles and materialized cells can prevent content-based correspondence, even when the physical styles match. Such sheets remain separate `sheet_observation` records requiring review; the engine does not infer a rename, addition or deletion. Matching sheet names still permit representation-independent physical formatting comparison.

A change's `before_blank_style_range` and `after_blank_style_range` bound the physical difference band, while each range's `source_ref` still identifies its original source rectangle. The endpoint cell is a representative at the band's top-left coordinate. Its `source_range` always names the complete original rectangle; its `difference_range` names the compared band. For example, a change in the last 20 rows of source `A1:CV100` reports `source_range=A1:CV100` and `difference_range=A81:CV100`. Cells synthesized for ordinary viewport reads carry `source_range` without `difference_range`. Native details label original and differing ranges separately.

There are at most 100,000 stored rectangles per input and across all revisions in a report. Worksheet coordinates remain bounded to 1,048,576 rows and 16,384 columns; rectangle/cell and rectangle/rectangle overlaps are rejected without area expansion. Cell/range reads synthesize at most 40,000 physical cells per viewport, matching the query's 200×200 maximum. The native preview remains at most 100×12 cells. Full-sheet search and net comparison retain rectangles, while `list_workbook_formatting_ranges` provides paged range/style-reference evidence without expanding their area. Formula/range intersection and active-interval comparison work each have a 2,000,000-operation bound; exceeding a bound fails without committing a partial report.

CLI entry points: `workbook-analyze --manifest <json> --store <library>`, `workbook-query --project <wprj_ID> --report <wreport_ID> --tool <tool> --args <json>`, and `workbook-export --project <wprj_ID> --report <wreport_ID> --out <directory>`. Manifests contain `title` and ordered `revisions` with `label`, relative/absolute `path`, optional `expected_sha256`. Local export preserves originals by SHA filename and emits quoted Markdown, JSON and JSONL.

## Review-driven consumer corrections

Cell styles are interned in per-revision `style_definitions` with stable semantic `style_ref` IDs. Their full content remains in the immutable report; raw cell readers resolve the reference before exposing style fields. Budget charging counts distinct style definitions, while actual cell contents remain individually bounded. Style-definition tables do not spill into version-summary or native view responses. Changes to workbook defaults remain semantic observations.

Change lists and `get_workbook_change component=summary` return bounded identifiers, endpoints, physical addresses and interpretation summaries. `component=before|after` returns one source cell, with the same text continuation contract as a cell read. For `formatting_range` events, this is the representative top-left blank observation with separate original `source_range` and clipped `difference_range` provenance. This avoids duplicating both cells into multiple MCP envelopes. Native grids use a compact preview-specific projection; selected-cell evidence remains independently paged.

Workbook stages are recovered during app startup under the exclusive library lock. A cancelled or failed native operation discards only its owned staged run before releasing admission; a new run removes its superseded stages. Neither workbook initialization nor its smoke driver starts through a locked second process. Each comparison pane highlights its actual source coordinate, including distant row moves.

Cell reads also expose one canonical cell in `items[0]`, not a second top-level copy. `availability=not_materialized` uses an empty items array; this differs from a materialized blank cell. Every continuation belongs to its cell field.

JSONL exports begin with one `record_type=workbook_manifest` carrying fixed identities and per-revision style definitions, plus per-sheet `blank_style_ranges` for engine 1.1 reports, followed by `record_type=workbook_change` records. Shared style dictionaries are written once; readers resolve `style_ref` against the corresponding source occurrence. Markdown links to the paired authoritative JSON for full definitions. Engine 1.0 exports retain their previous manifest shape so existing export identities do not acquire different bytes.

Lifecycle Bridge actions include `workbookDiscard({project_id,analysis_run_id})` and read-only `workbookRunStatus({project_id,analysis_run_id})`, scoped to an exact owned run. They are internal app/CLI operations, not MCP tools. Once a transaction commits, stage cleanup failure returns `cleanup_pending` without reversing the saved outcome. The native app checks the exact server-side run after an uncertain commit reply and distinguishes saved, cancelled and unconfirmed results. Startup cleanup errors appear as warnings while document comparison remains available.

XLSX formatting application flags remain raw evidence in interned styles. Explicit false inherits the applicable base/default group; explicit true uses the direct group/fallback. Conflicting omitted-flag semantics carry a `style_application` gap rather than a renderer-equivalence claim. Primary string extraction excludes phonetic guides from cell values, preserves ODS space/tab/line-break controls and bounds their expansion. Namespace authority is enforced at actual roots/cell structures; unexecuted conditional-format/drawing/filter/extension metadata yields named gaps instead of making an otherwise readable workbook fail.

## Source authority and bounded reads

Allocated XLSX cells use their own `s` index or style 0 when it is absent, per the [ISO-derived cell schema](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/how-to-insert-a-chart-into-a-spreadsheet#cell-element). Column defaults affect [unallocated cells](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.column?view=openxml-3.0.1); they do not override an already allocated cell lacking `s`. ODS valued cells continue to inherit defaults under its own format rules.

Empty numeric formula cache placeholders are unavailable results, not confirmed blank-type edits. Cached empty strings, numeric zero and explicit input blanks remain distinct. Missing-cache transitions preserve cache-availability events without asserting value/type edits.

The run charges a cumulative serialized UTF-8 lower bound for each revision and change before retaining it, then checks the exact final canonical report including headers and gaps. Oversized or unrepresentable reports fail with `WORKBOOK_REPORT_LIMIT` before a partial report can commit. The parser's 64 × 1024 × 1024-unit text counter counts UTF-16 code units in parsed shared strings, materialized values/formulas, distinct number formats and distinct style definitions; it is conservative across parsed and materialized representations. Archive/file/report and wire limits use bytes.

Consumed XLSX style definitions and nested properties require SpreadsheetML namespaces. Style keys distinguish XML attributes from child elements: `font.color.@rgb` is an attribute; `font.color.rgb` is a child element. Attribute names and element names preserve canonical namespace prefixes, with `%` and `.` escaped inside each path segment to keep paths unambiguous. ODS examples include `text-properties.@fo:font-weight`; a `style:font-weight` attribute or `fo:font-weight` child cannot overwrite it. Number-style evidence uses canonical semantic prefixes for recognized namespaces (including one `r` prefix for both OOXML relationship dialects) and retains the full unknown URI otherwise. Extension properties remain distinct and explicitly outside rendering equivalence. Calculation settings accept only attributes owned by the source format, with other settings omitted under a coverage gap.

ODS number-format serialization is bounded to 16,384 UTF-16 code units during traversal; nested children are serialized once without re-escaping a previously serialized child. XLSX format-code text has the general 1 MiB field limit. Each distinct materialized number format is charged once against the parser text budget, in addition to parsed source definitions; cell values/formulas remain individually charged. Analysis counts each occurrence's escaped UTF-8 JSON bytes before allocating the complete revision string, rejecting oversized revision/change content early. The final canonical report, including header and duplicated coverage overhead, is checked separately against 256 MiB; no partial result is committed. These limits apply jointly with the cell count cap.

Sheet source locators are limited to 480 UTF-16 code units. Longer in-package worksheet paths fail input validation; this is independent of the host file path. XLSX style descendants outside SpreadsheetML are rejected except excluded `extLst` metadata, which produces a coverage gap. Ignorable markup outside that exclusion is not a complete Markup Compatibility implementation.

The current same-Mac private package qualification is recorded in [WORKBOOK-2026-10-22.md](WORKBOOK-2026-10-22.md). Earlier provisional builds also used `workbook.1.0` while parser semantics were being corrected; those experimental reports are not qualified by the new tests. Stored report bytes remain unchanged. Analyze the originals again for current extraction semantics.

Imports require a regular source file selected directly. Native selection and workbook reads atomically reject a final-component symlink and nonregular files, including writerless FIFOs, before reading; a rejected special file cannot stall waiting for a writer. This is not a guarantee against every network or stalled regular-file I/O condition.

Persistent MCP readers retain at most two net diffs/16 MiB. Native helpers are short-lived: nonadjacent net pages re-read their two endpoints, while adjacent comparisons use stored changes. Searches still scan scoped cell indexes, but only current-page candidates receive style resolution and text projection. Metadata is bounded but parsed in full; these paths have no constant-latency guarantee. Sheet metadata pages may require a smaller `metadata_limit` to fit the requested wire budget. Differently named unmatched sheets across formats remain `needs_review`; inspect their version contents separately instead of assuming a semantic pairing.
